## 1. 코딩테스트란?

코딩테스트는 IT 관련 기업이나 기관에서 지원자를 선발하기 위해 진행하는 일종의 **문제 풀이 시험**입니다.

단순히 문법을 알고 있는지를 확인하기보다는, 주어진 문제를 분석하고 적절한 알고리즘과 자료구조를 활용해 제한 시간 안에 해결할 수 있는지를 평가합니다.

---

## 2. 코딩테스트 종류

### 2.1 알고리즘 코딩테스트

정해진 시간 동안 여러 개의 알고리즘 문제를 해결하는 방식입니다.

- 정해진 시간 안에 여러 개의 알고리즘 문제가 주어진다.
- 문제에 적절한 알고리즘을 선택할 수 있어야 한다.
- 작성한 코드가 정확한 결과를 출력해야 한다.
- 입력 크기에 따라 시간 복잡도까지 고려해야 한다.

> **핵심**
>
> 알고리즘 코딩테스트에서는 단순 구현 능력뿐 아니라  
> **문제 분석 → 알고리즘 선택 → 구현 → 복잡도 검토**의 전체 과정을 평가합니다.

### 2.2 개발 과제 코딩테스트

하나의 완성된 프로그램이나 기능을 개발하는 것을 목표로 하는 시험입니다.

- 짧게는 몇 시간, 길게는 2주 이상의 시간이 주어질 수 있다.
- 실제 서비스와 비슷한 요구사항이 주어지기도 한다.
- 특정 회사에서 사용하는 언어 또는 프레임워크를 활용하도록 요구하기도 한다.
- 코드 구조, 가독성, 유지보수성, 테스트 코드 등이 평가 대상에 포함될 수 있다.

## 3. 시험 환경에 따른 분류

### 3.1 온라인 코딩테스트

특정 웹사이트에서 문제를 읽고 코드를 작성한 뒤 제출하는 방식입니다.

- 공개 채용 과정에서 많이 사용된다.
- 응시자는 일반적으로 혼자 힘으로 문제를 해결해야 한다.
- 표절 검사를 진행하는 경우가 많다.
- 인터넷 검색 허용 여부는 시험마다 다르다.
- 검색이 허용되더라도 단순 검색으로 정답이 바로 나오는 문제는 잘 출제되지 않는다.

#### 온라인 개발 환경

코딩테스트를 공부할 때는 브라우저에서 제공되는 온라인 개발 환경을 사용할 수 있습니다.

예시:

- Replit
- 온라인 저지 사이트의 코드 실행 환경
- 브라우저 기반 IDE

> 실제 시험에서는 시험 플랫폼 자체 편집기를 사용하는 경우가 많으므로  
> **자동완성이나 IDE 기능에 지나치게 의존하지 않는 연습**도 필요합니다.

### 3.2 오프라인 코딩테스트

기업 또는 기관의 시험장에 방문하여 치르는 방식입니다.

- 시험장에서 제공하는 컴퓨터를 사용하는 경우가 많다.
- 인터넷 검색 허용 여부는 기관마다 다르다.
- 개발 환경과 설치된 도구가 제한될 수 있다.
- 평소 사용하던 IDE가 아닌 환경에서도 문제를 풀 수 있도록 준비하는 것이 좋다.

## 5. IT 기업 코딩테스트 출제 경향

많은 IT 기업에서는 공개 채용 과정에서 알고리즘 코딩테스트를 활용합니다.

일반적으로:

- 약 **2~5시간**의 시험 시간이 주어진다.
- 여러 개의 알고리즘 문제를 해결해야 한다.
- 구현 문제가 자주 출제된다.
- DFS / BFS와 같은 탐색 문제가 자주 등장한다.
- 탐욕법(Greedy) 문제도 자주 출제된다.

자주 연습해 둘 만한 유형:

1. 구현
2. 문자열
3. 정렬
4. 탐욕법
5. 이진 탐색
6. DFS / BFS
7. 백트래킹
8. 다이나믹 프로그래밍
9. 최단 경로
10. 투 포인터 / 누적합

## 6. 코딩테스트 준비 방법

### Step 1. 프로그래밍 언어 선택

먼저 자신에게 맞는 프로그래밍 언어를 선택하고 기본 문법을 충분히 익힙니다.

대표적인 언어:

- Python
- C++
- Java
- JavaScript

이 학습에서는 **JavaScript**를 기준으로 진행합니다.

### Step 2. 알고리즘 유형별 학습

각 알고리즘의 개념을 학습한 뒤 대표 문제를 반복해서 풉니다.

권장 방식:

1. 알고리즘 이론 이해
2. 기본 코드 직접 구현
3. 쉬운 문제 풀이
4. 응용 문제 풀이
5. 틀린 문제 다시 풀기

각 유형별로 최소 **10개 이상의 핵심 문제**를 풀어보는 것을 목표로 합니다.

### Step 3. 지원 기업의 기출 문제 풀이

지원하고 싶은 기업이 있다면 해당 기업의 기출 문제나 유사 문제를 풀어보는 것이 좋습니다.

기업마다 자주 출제하는 유형과 난이도가 다를 수 있기 때문입니다.

## 7. 시간 복잡도

시간 복잡도(Time Complexity)는 알고리즘의 성능을 나타내는 중요한 척도입니다.

> **시간 복잡도**
>
> 특정 크기의 입력이 주어졌을 때 알고리즘의 연산 횟수 또는 수행 시간이 얼마나 증가하는지를 나타냅니다.

동일한 기능을 수행하는 알고리즘이라면 일반적으로 시간 복잡도가 낮을수록 더 효율적입니다.

예를 들어:

```text
O(N)  → 입력 크기에 비례하여 증가
O(N²) → 입력 크기의 제곱에 비례하여 증가
```

---

## 8. Big-O 표기법

Big-O 표기법은 입력 크기가 증가할 때 알고리즘의 수행 시간이 얼마나 빠르게 증가하는지를 표현하는 방법입니다.

가장 빠르게 증가하는 항만 고려합니다.

예를 들어 다음과 같은 연산 횟수가 있다고 가정합니다.

```text
3N³ + 5N² + 1,000,000
```

`N`이 충분히 커지면 `3N³`의 영향이 가장 커집니다.

따라서 Big-O 표기법으로는 계수를 제외하고 다음과 같이 표현합니다.

```text
O(N³)
```

### 대표적인 시간 복잡도

| Big-O | 이름 | 특징 |
|---|---|---|
| `O(1)` | 상수 시간 | 입력 크기와 관계없이 일정 |
| `O(log N)` | 로그 시간 | 입력이 커져도 증가 폭이 매우 작음 |
| `O(N)` | 선형 시간 | 입력 크기에 비례 |
| `O(N log N)` | 로그 선형 시간 | 효율적인 정렬 등에서 자주 등장 |
| `O(N²)` | 이차 시간 | 이중 반복문에서 자주 등장 |
| `O(N³)` | 삼차 시간 | 큰 입력에서는 사용이 어려움 |
| `O(2^N)` | 지수 시간 | 입력이 조금만 증가해도 연산량이 폭발적으로 증가 |

대략적인 효율 순서는 다음과 같습니다.

```text
효율적                                              비효율적

O(1)
  ↓
O(log N)
  ↓
O(N)
  ↓
O(N log N)
  ↓
O(N²)
  ↓
O(N³)
  ↓
O(2^N)
```

---

## 9. 시간 복잡도 예시

### 9.1 예시 1 — 배열의 모든 원소 합 구하기

```javascript
const array = [3, 5, 1, 2, 4];

let summary = 0;

for (let i = 0; i < array.length; i++) {
  summary += array[i];
}

console.log(summary);
```

배열의 원소 개수가 `N`개라면 반복문도 `N`번 실행됩니다.

따라서 시간 복잡도는:

```text
O(N)
```

입니다.

### 9.2 예시 2 — 이중 반복문

```javascript
const array = [3, 5, 1, 2, 4];

for (let i = 0; i < array.length; i++) {
  for (let j = 0; j < array.length; j++) {
    const temp = array[i] * array[j];
    console.log(temp);
  }
}
```

외부 반복문이 `N`번 실행되고, 각 반복마다 내부 반복문도 `N`번 실행됩니다.

대략적인 연산 횟수는:

```text
N × N = N²
```

따라서 시간 복잡도는:

```text
O(N²)
```

입니다.

> **주의**
>
> 모든 이중 반복문의 시간 복잡도가 무조건 `O(N²)`인 것은 아닙니다.
> 반복 범위가 어떻게 변하는지 확인해야 하며, 내부에서 다른 함수가 호출된다면 그 함수의 시간 복잡도도 함께 고려해야 합니다.

## 10. 알고리즘 설계 Tip

코딩테스트에서는 문제를 풀기 전에 **입력 크기와 시간 제한을 먼저 확인하는 습관**이 중요합니다.

JavaScript에서도 단순 연산을 매우 많이 수행하면 실행 시간이 크게 증가할 수 있으므로, 정확한 연산 속도를 고정된 숫자로 생각하기보다는 **대략적인 기준**으로 판단하는 것이 좋습니다.

### 예시: `O(N³)` 알고리즘

만약:

```text
N = 5,000
```

이라면 연산 횟수는 대략:

```text
5,000³
= 125,000,000,000
```

즉 약 **1,250억 번**의 연산 규모이므로 일반적인 코딩테스트 시간 제한 안에 처리하기 어렵습니다.

### 문제를 읽으면 가장 먼저 확인할 것

```text
1. 시간 제한
2. 입력 크기 N
3. 요구하는 출력
4. 사용할 수 있는 알고리즘의 시간 복잡도
```

> 문제를 읽자마자 코드를 작성하지 말고  
> **입력 크기로 가능한 시간 복잡도를 먼저 추정합니다.**

## 11. 입력 크기에 따른 시간 복잡도 기준

시간 제한이 약 **1초**라고 가정했을 때 참고할 수 있는 대략적인 기준입니다.

| 입력 크기 `N` | 고려할 수 있는 시간 복잡도 |
|---:|---|
| `N ≤ 500` | `O(N³)` |
| `N ≤ 2,000` | `O(N²)` |
| `N ≤ 100,000` | `O(N log N)` |
| `N ≤ 10,000,000` | `O(N)` |

> 이 기준은 절대적인 값이 아닙니다.
>
> 실제 실행 시간은 다음 요소에 따라 달라질 수 있습니다.
>
> - 프로그래밍 언어
> - 채점 서버 성능
> - 입출력 양
> - 상수 시간 연산의 크기
> - 재귀 호출 여부
> - 문자열 처리
> - 자료구조 사용 방식

따라서 위 표는 **알고리즘을 선택하기 위한 빠른 판단 기준**으로 활용합니다.

## 핵심 정리

- 코딩테스트는 문제 해결 능력과 알고리즘 활용 능력을 평가하는 시험이다.
- 알고리즘 코딩테스트와 개발 과제형 코딩테스트가 있다.
- 시험은 온라인 또는 오프라인으로 진행될 수 있다.
- 자주 사용하는 알고리즘 코드는 자신만의 템플릿으로 정리하는 것이 좋다.
- 코딩테스트에서는 **시간 복잡도**가 매우 중요하다.
- Big-O는 입력 크기에 따른 알고리즘의 성능 증가 정도를 나타낸다.
- 문제를 읽으면 가장 먼저 **시간 제한과 입력 크기**를 확인한다.
- 입력 크기를 보고 사용할 수 있는 알고리즘의 시간 복잡도를 추정하는 습관이 중요하다.
